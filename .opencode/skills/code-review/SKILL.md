# Когда использовать

Когда просят проверить ветку, PR или чужие изменения. Только чтение: код не править, пока
человек не попросил.

Перед началом прочитай `AGENTS.md`, особенно разделы 0, 5, 10 и 12.

# Порядок

1. Возьми задачу и ветку. Посмотри `git fetch origin` и `git diff origin/main...HEAD`.
2. Прочитай изменённые файлы целиком, а не только диф.
3. Проверь по чек-листу ниже.
4. Верни отчёт: блокеры, предложения, мелочи. Для каждой находки — `путь:строка` и почему
   это важно.
5. Если данных не хватает, задай вопрос, а не догадывайся.

# Чек-лист

- Задача и объём: изменения решают задачу и не тащат следующий этап.
- Зоны: чужие файлы не сломаны, схема БД не правится без владельца.
- Контракт: если затронут API, обновлён `docs/api.md`, типы совпадают.
- Сервер: права, лимиты, пересечения и отмена проверяются на сервере, а не только на клиенте.
- Гонки: бронь в транзакции, ограничение `UNIQUE (machine_id, date, slot_start)` на месте.
- Безопасность: bcrypt, нет секретов и токенов в логах, zod на входе, параметризованные запросы.
- Фронтенд: страницы ходят только в `api/`, нет UI-библиотек, стили в CSS Modules, есть
  загрузка, ошибка и пустое состояние.
- Доступность: label, клавиатура, видимый фокус, ошибки с `aria`.
- Тесты: новые правила покрыты, старые тесты не удалены и не ослаблены.
- Миграции: новая миграция вместо правки старой.
- Размер: PR можно отревьюить за один заход.
