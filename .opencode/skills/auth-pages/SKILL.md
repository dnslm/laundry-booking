# Когда использовать

При изменениях в `frontend/src/pages/LoginPage`, `RegisterPage`, `components/Button`,
`FormField`, `ErrorMessage`, `AuthShell`, `auth/`, `api/auth.ts`, `api/mocks.ts`.

Перед началом прочитай `AGENTS.md`, особенно разделы 0, 4, 11 и 12.

# Контекст

- Вход по логину и паролю. JWT-заглушка хранится в `localStorage` под ключом `laundry.token`.
- Пока бэкенда нет, `api/auth.ts` работает на моках из `api/mocks.ts`.
- Демо-аккаунты: `student / student123`, `admin / admin123`.
- Регистрация создаёт студента и сразу входит в аккаунт.
- Все пользователи после входа попадают на `/booking`.

# Правила

- Страницы не ходят в сеть напрямую и не импортируют `mocks.ts`: только `useAuth()` и `api/`.
- Не менять контракт API молча. Если меняются поля или ошибки, сначала согласовать с командой.
- Валидация на клиенте повторяет серверные правила, но не заменяет их.
- Пароль: от 8 до 72 символов, повтор обязателен.
- Логин: 3–20 символов, латиница, цифры и `_`.
- Контакт: телефон 10–11 цифр, Telegram 5–32 символа, VK — ссылка или короткое имя.
- Ошибки сервера показывать в баннере, ошибки поля — под полем. Для `login_taken` использовать поле `login`.
- Не логировать пароли и токены.

# Стиль

- Смотри `AGENTS.md`, раздел 11. Шрифт Golos Text, тёмно-синий сплит, логотип кампуса.
- Без клеток и паттернов на фоне, без клишированных маркетинговых фраз.
- Поля и кнопки 44px, радиус 3px, фокус 2px ярко-синий.
- На телефоне одна колонка, форма ниже синей шапки, без горизонтальной прокрутки.

# Проверки

```bash
yarn workspace frontend dev
yarn lint
yarn format:check
yarn types
yarn tests
yarn build:all
```

Ручной сценарий: неверный пароль, вход студентом, перезагрузка, регистрация, дубликат
логина, мобильная ширина 390px. Если менял вёрстку — проверь 1440px и 390px.
