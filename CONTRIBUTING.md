# Как работать над проектом

## Ветки и коммиты

- `main` всегда рабочая. Прямых коммитов в неё нет, только через Pull Request.
- Одна задача = одна ветка = один PR. Ветка живёт 1-3 дня.
- Названия веток: `feat/...`, `fix/...`, `docs/...`, `chore/...`.
- Сообщения коммитов: `feat: добавил проверку пересечения слотов`.
  Заголовок PR оформляем так же: он станет сообщением squash-коммита.

## Цикл работы

```bash
git switch main && git pull
git switch -c feat/короткое-название
# работа, маленькие коммиты
git fetch origin && git merge origin/main
git push -u origin feat/короткое-название
# открыть Pull Request на GitHub
```

## Pull Request

- Нужны один апрув от другого участника и зелёная проверка `check`.
- Свои PR не мерджим. Мердж только через Squash and merge.
- Ревью делаем в течение суток. Если висит дольше, пингуем в чате.
- В описании пишем `Closes #номер`, чтобы задача закрылась сама.

## Правила

- Схему БД (`backend/prisma/schema.prisma`) меняет только её владелец.
  Нужно изменение: пишешь владельцу или делаешь маленький отдельный PR. Старые миграции не правим.
- Сначала контракт API в `docs/api.md`, потом код.
- Секреты не коммитим: настоящий `.env` в `.gitignore`, в репозитории только `.env.example`.
- Перед коммитом автоматически запускаются ESLint и Prettier. Если хук ругается, исправь замечания.
